# CampusOverflow 团队代码评审清单 v1.0

> 仓库：`baga1234-q/campus-todo-team-four`
> 维护：王（SM / QA 兼职）
> 版本：v1.0　|　状态：生效中
> 用途：所有 PR 在合并前，评审人按本清单逐项检查并留下**可验证、可执行**的评审意见。

---

## 1. 评审底线（硬性门槛，任一不满足即打回）

- [ ] PR 关联了 Issue（正文含 `Closes #编号`）
- [ ] 功能分支命名符合 `feature/<issue号>-<主题>`，未直接向 `main` 提交
- [ ] 提交信息符合 `<type>: <说明>` 规范（feat/fix/test/docs/ci/chore/refactor）
- [ ] CI 通过（PR Checks 显示 `build` 绿色）
- [ ] 作者不是本 PR 的 Approve 人

## 2. 需求与验收

- [ ] 改动完整覆盖 Issue 的验收标准，无遗漏功能
- [ ] 与看板卡片 / 用户故事（`docs/backlog/stories/*.feature`）行为一致
- [ ] 未引入需求范围外的无关改动（保持 PR 小且聚焦）

## 3. 功能正确性

- [ ] 正常路径逻辑正确，结果符合预期
- [ ] 边界条件已处理：空输入、空白标题、负数/不存在编号、重复操作
- [ ] 异常路径有明确处理：抛出有意义的异常或返回明确错误提示
- [ ] 完成/重复完成等状态转换符合业务规则（参考 `002-complete-task.feature`）
- [ ] 优先级取值限定在 HIGH / MEDIUM / LOW，非法值被拒绝

## 4. 代码质量

- [ ] 命名清晰：类、方法、变量名表达真实意图
- [ ] 方法职责单一、可读性好，无复制粘贴重复代码
- [ ] 无明显死代码、注释掉的旧代码、调试输出残留
- [ ] 没有把敏感信息（密码、令牌、密钥）硬编码进代码或配置文件
- [ ] 不提交构建产物（target/）、IDE 配置（.idea/）等无关文件

## 5. 测试质量

- [ ] 为新增行为编写了单元测试（先写测试或至少与实现同 PR 提交）
- [ ] 测试覆盖关键正常路径与至少一个异常/边界用例
- [ ] 本地 `mvn test` 全部通过（与 CI 结果一致）
- [ ] 测试命名表达行为（如 `shouldRejectBlankTitle`），而非只重复实现

## 6. 文档同步

- [ ] 行为变化已同步 README（功能清单、验收说明）
- [ ] 新增/修改的用户故事与看板状态一致
- [ ] 若涉及构建/部署配置（CI、docker 等），README 或对应文档已更新

## 7. 评审意见规范

- 意见须**可验证、可执行**：指出具体文件/行号/场景 + 期望行为，例如：
  - ❌ "代码写得不错" / "LGTM"
  - ✅ "`TaskService.complete` 对不存在 id 未抛异常，请补 `TaskNotFoundException` 及对应测试，参考 002 场景 3"
- 评审人至少 1 人 Approve 后才允许合并；意见全部解决后由作者在功能分支上补充提交。
